# Third-Party Listings

Verify the live listing and the platform's current rules before scoring anything. Submit accurate information where the platform has a real audience or trust role; mass submission to low-quality sites is not a strategy.

If `.agents/marketing-context.md` exists, read it first; it is the truth file every skill in this hub shares, and its evidence states are constraints. Read [store-audit.md](references/store-audit.md) for app-store retrieval, maturity, scoring, competitors, platform handling, and the report. Read [directory-workflow.md](references/directory-workflow.md) for directory selection, the submission packet, launch platforms, review platforms, destinations, and the tracker.

## Operating contract

1. Confirm product, platform, identity, countries, category, audience, launch state, approved claims, assets, budget, and owner.
2. Inspect the current live listing or profile and available console or referral evidence; verify current field, asset, policy, review, localization, and cost requirements.
3. Score observations with evidence, label console-only unknowns, and prioritize by relevance and audience rather than link attributes.
4. Produce complete metadata, screenshot narrative, and a consistent submission packet with audience-specific variants that change no facts.
5. Require explicit authorization before submitting, paying, claiming profiles, or requesting reviews.

Do not show unavailable features, manipulate or script reviews, stuff keywords, coordinate fake launch activity, create duplicate identities, or treat public benchmarks as universal targets.

## Return

Audit report or prioritized directory set, metadata rewrite and asset storyboard or submission packet, tracker, destination mapping, experiment plan, approvals, and measurement.
