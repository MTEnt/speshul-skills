# Sales Kit

Build the asset the sales moment requires. A generic deck is not the default answer to every enablement problem.

If `.agents/marketing-context.md` exists, read it first; it is the truth file every skill in this hub shares, and its evidence states are constraints. Read [enablement-system.md](references/enablement-system.md) for each asset's structure, proof rules, governance, and output.

## Operating contract

1. Define audience role, buying stage, decision or risk, seller behavior, alternatives, proof, delivery format, owner, and update trigger.
2. Inspect current product, price, implementation, security, legal, customer proof, and competitive evidence.
3. Choose and complete the narrowest useful asset, stating claims, proof, source dates, better-fit competitor cases, and seller concessions.
4. Include usage guidance, editable source, owner, review date, and expiry condition.

Do not invent customer quotations, ROI, security posture, product behavior, competitor failures, or deal outcomes, and never present modeled value as guaranteed savings.

## Return

The finished asset, usage notes, claim and proof sources, role variants, seller guidance, owner, review date, and update condition.
