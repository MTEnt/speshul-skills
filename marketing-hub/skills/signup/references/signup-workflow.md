# Signup workflow

## Field review

For each field capture purpose, necessity now or later, source, expected value, format, input type, autocomplete, password-manager behavior, validation owner, error text, recovery, privacy impact, and downstream consumer. Never collect data merely because a CRM has a column.

## Flow choice

Use a single step when requirements are few and familiar. Use multiple steps when sequencing improves understanding, branching prevents irrelevant work, expensive verification should happen later, or saved progress matters. Show progress only when it is meaningful and accurate.

Evaluate email and password, magic link, passkey, SSO, social identity, invite-based access, trial without account, and assisted setup against audience, security, account linking, support, and recovery. Prevent duplicate identities across methods.

## Trust and effort

Explain why sensitive information is needed, what the trial or commitment includes, whether payment is required, renewal behavior, terms, and what happens next. Preserve user input after errors and interruptions.

## Mobile and accessibility

Use correct keyboard and input modes, visible labels, large targets, password-manager compatibility, error focus, live-region behavior, zoom-safe layout, minimal context switching, and a verification path that does not strand the user on another device.

## Post-submit states

Cover loading, duplicate submission, existing account, verification sent, expired or reused link, account created, partial setup, external provider failure, blocked account, and safe retry. Make the next useful action explicit.

## Common patterns

Adapt self-serve trial, freemium, invite-only, team workspace, marketplace two-sided, regulated onboarding, and sales-assisted account creation. Do not force the same fields or commitment across all models.

## Measurement and experiments

Track eligible start, step completion, field error, verification, account creation, duplicate account, support contact, fraud, first useful action, and retained activation. Candidate experiments include field timing, path choice, step sequence, expectation copy, verification timing, and error recovery.

## Output

Return current-flow evidence, bottleneck, revised journey, field table, complete interface copy, all states, event plan, security and privacy constraints, implementation dependencies, and ship or experiment decision.
