# Activation workflow

## Activation models

Choose an observable behavior or set of behaviors that indicates useful progress and predicts retained value. Distinguish:

- setup completion;
- first meaningful action;
- first useful result;
- repeated value within an appropriate window;
- team or network activation;
- assisted activation for complex products.

Validate the relationship with cohort evidence where available. A plausible event is not automatically a proven leading indicator.

## Minimum path to value

Map account creation, prerequisites, configuration, data import, collaboration, core action, output, and confirmation. Mark each step required now, safely deferred, automatically inferred, optional, or removable.

For every retained step specify user goal, reason now, input, validation, empty/loading/success/error states, saved progress, example or template, event, skip or exit, and recovery.

## Component toolkit

Use only when it solves a real obstacle: welcome choice, role or use-case branch, sample data, template, setup checklist, contextual hint, interactive walkthrough, empty-state prompt, progress indicator, import assistant, concierge help, lifecycle reminder, team invitation, milestone celebration, or help center.

## Psychology and trust

Support autonomy, visible progress, confidence, meaningful defaults, reversible exploration, and early evidence of value. Avoid forced tours, fake completion, arbitrary gamification, and hiding required work until late.

## Multi-channel journey

Coordinate product, email, SMS only with permission, sales, customer success, documentation, and support. Every message needs eligibility, trigger, stop condition, and suppression after completion.

## Stalled-user recovery

Classify missing prerequisite, unclear next action, technical failure, insufficient value, lack of authority, data concern, team dependency, or bad fit. Match assistance to the cause. Preserve a respectful exit for bad-fit users.

## Product patterns

Adapt single-player tools, collaborative workspaces, data products, developer tools, marketplaces, ecommerce, regulated products, and high-touch enterprise implementations. Define activation per side or role when journeys differ.

## Experiments

Test setup order, field timing, templates, sample data, guidance, branch logic, assisted help, team invitation, and product behavior. Protect security, support load, account quality, retained value, and accessibility.

## Output

Return evidence, activation definition, minimum path, detailed states and copy, channel journey, recovery paths, event plan, experiments, owners, and implementation dependencies.
