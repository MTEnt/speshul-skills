# Marketing Context

Build the factual foundation other marketing work can safely reuse. Distinguish inspected facts, user assertions, analysis, hypotheses, and unknowns. Do not turn website claims, synthetic personas, or a few public comments into verified customer truth.

## Route the task

- Use `$product-marketing` for the reusable context file, ICP and buying roles, positioning inputs, proof, objections, and voice.
- Use `$customer-research` for interviews, surveys, transcripts, reviews, public-signal research, voice of customer, and evidence-grounded personas.
- Use `$competitor-profiling` for competitor discovery, dossiers, alternative sets, category maps, and competitive evidence.

Use multiple canonical skills only when the requested decision crosses them. Each can operate independently when installed alone.

## Operating rules

1. Name the decision the context must support.
2. Inspect existing project and research sources before asking the user to repeat information.
3. Browse current primary sources for external product, pricing, policy, and market facts.
4. Preserve verbatim customer language with source and context; do not claim frequency without a defensible sample.
5. Record counterevidence and bad-fit segments, not only supportive evidence.
6. Create or update `.agents/marketing-context.md` when durable shared context is part of the task. Show substantive changes and preserve a short revision history. Do not create a competing context file when an authoritative one already exists.
7. Return the reusable artifact plus unresolved questions and the next validation needed.

Do not publish research, contact participants, scrape restricted sources, or store sensitive personal data without authorization and a legitimate need.
