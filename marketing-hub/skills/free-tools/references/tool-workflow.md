# Free-tool workflow

## Tool types

- calculator or estimator;
- grader, checker, or validator;
- generator or transformer;
- template builder;
- interactive assessment;
- benchmark explorer;
- searchable database or directory;
- visualization or simulator;
- product sandbox or sample-output creator;
- migration, compatibility, or diagnostic utility;
- API, library, command-line tool, or open-source component.

## Idea selection

Start from recurring audience work, difficult calculations, high-friction comparisons, required validation, product prerequisites, sales questions, support patterns, and useful internal tools that can be safely externalized.

Compare usefulness, audience fit, differentiation, product proximity, data availability, build cost, maintenance, search potential, sharing, privacy, security, support, and time to signal.

## Product contract

```text
Audience and task:
Inputs and validation:
Data sources and freshness:
Calculation or transformation:
Output and explanation:
Normal, empty, error, and extreme states:
Privacy, retention, consent, and security:
Performance and usage limits:
Accessibility and mobile:
Analytics events:
Owner and maintenance:
Stale-data and retirement behavior:
```

Expose assumptions and formulas where users need them to interpret the result.

## Gating

Prefer ungated value when sharing, search, and trust drive the mechanism. Use preview-then-gate or saved-result access only when the additional value justifies contact collection. Never withhold a promised result after inputs are submitted without making that condition clear beforehand.

## Search and distribution

Create a useful explanatory page, method, examples, output URLs only when they contain distinct value, metadata, structured data where valid, internal links, and a path to the product. Avoid indexable thin output pages and user-data leakage.

## Build or buy

Buy or embed when a maintained commodity component meets privacy, branding, performance, and data requirements. Build when the logic, experience, integration, or evidence is differentiating and maintainable.

## MVP

Implement the smallest input-to-useful-output path with deterministic logic, clear assumptions, share or save only when needed, and complete failure states. Defer accounts, dashboards, collaboration, and elaborate personalization unless the value requires them.

## Evaluation

Measure qualified use, completion, repeat use, shares, links, output usefulness, product activation, pipeline, support, abuse, infrastructure cost, and maintenance. Stop or simplify when attention does not translate into useful outcomes.

## Deliverable

Return selected concept, rejected ideas, product specification or working implementation, data and rights risks, distribution, lifecycle handoff, measurement, QA, and maintenance plan.
